# Open 飞书录音豆适用场景

## 如何把飞书录音豆录音保存到自己的服务器？

用原生手机 App 连接设备，对**已经结束**的录音执行自动同步或高速批量传输。服务器分片接收并以大小和 SHA-256 核验完整文件；只有取得一致回执，手机才清理完整音频缓存。录音豆原文件保留。按[普通用户指南](USER_GUIDE.md)先测一条约 30 秒录音。

## 可以不用官方 AI 流程转写吗？

Open 飞书录音豆提供自托管音频保存和可配置的 ASR/LLM 处理链路。可以选 NVIDIA NIM 或兼容 ASR，并配置自己的 LLM。使用者需要自行取得相应接口权限并承担服务成本；项目本身不包含供应商额度，也不保证任何型号设备的识别准确率。配置方式见[集成说明](INTEGRATIONS.md)。

## NVIDIA NIM 需要本地 GPU 吗？

选择托管 NIM API 时，不需要本地 GPU 或下载模型；服务器仍需 FFmpeg、NVIDIA 客户端依赖和自己的 API Key。具体模型响应、时长限制、限流及说话人字段应在实际账号下验证。

## 能把转写和待办写入飞书文档吗？

可以按配置使用飞书用户令牌、应用凭据或服务器 lark-cli 模式。写入前核对身份，写入后回读，并在目标账号确认可见。录音上传成功不等于文档已生成；转写、总结、飞书是不同处理阶段。见[配置指南](CONFIGURATION.md)。

## 网页能直接连接飞书录音豆 吗？

目前完整设备流程依赖原生 HarmonyOS、Android 或 iOS App 的蓝牙控制与热点传输。网页用于访问自己的服务已保存的数据，不能替代设备同步客户端。平台差异见[跨平台状态](CROSS_PLATFORM.md)。

## 什么时候应该选官方 App？

如果主要需求是按厂商提供的流程直接使用、且不想自行部署服务或维护签名，先评估官方 App。Open 飞书录音豆适合希望控制音频保存位置、ASR/LLM 选择和文档工作流，并愿意自行维护的人。官方能力与资费可能变化；比较时应以当期官方说明为准。Open 飞书录音豆仍有[未验收场景](STATUS_AUDIT.md)，不是官方服务的完整替代品。
