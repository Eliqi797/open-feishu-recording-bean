# Open 飞书录音豆使用指南：同步、转写与飞书纪要

Open 飞书录音豆是一个面向飞书录音豆设备（型号 D3200 / soundcore Work）的个人自托管项目。手机 App 读取设备中的录音，将完整音频保存到自己的服务器，再按配置调用语音转写、总结和飞书文档服务。本项目不是安克、声阔、飞书或 NVIDIA 的官方产品，也不是提供账号注册的公共云服务。

本指南面向想在**自己的设备和服务器**上运行项目的人。源码可从公开 GitHub 仓库克隆，按 MIT 许可证使用；首次安装仍需要各平台的开发工具和自己的签名。各平台已完成部分真机验证，但长时间锁屏、长录音、多人重叠发言和长期后台运行尚未全部验收，详情见[跨平台状态](CROSS_PLATFORM.md)。

## 使用后会得到什么

1. 在 HarmonyOS、Android 或 iOS App 中扫描并连接飞书录音豆，查看设备状态、录音列表与电量。
2. 在「录音」页自动同步或点「高速传输」批量读取已结束的录音。完整录音上传后，服务器以大小和 SHA-256 核验；手机只在取得一致回执后清理完整音频缓存，**不会删除设备原文件**。
3. 按服务器设置转写、区分说话人、生成摘要和待办，并写入指定飞书身份下的云文档。录音卡片可打开文档；受保护回听仍需访问自己的服务器。
4. 在独立的「实时」页查看设备音频的分段转写。默认窗口为 5 秒，可选 2 / 5 / 10 / 20 秒；窗口长度不等于端到端出字延迟。结束设备录音后，再以完整文件的处理结果作为最终版本。

## 开始前准备

| 需要 | 用途 |
| --- | --- |
| 飞书录音豆设备及一台手机 | 测试时保持设备唤醒，先录一条约 30 秒、已停止保存的样本。 |
| Python 3.11+、FFmpeg、足够的磁盘空间 | 运行服务器、处理音频与兼容回听。NVIDIA NIM 调用远程 API，不需本地 GPU 或模型。 |
| 自己的 HTTPS 域名和服务器 | 手机跨网络上传、查询和回听；开发机的 `localhost` 只能供本机测试。 |
| 平台开发工具及个人签名 | HarmonyOS 用 DevEco Studio，Android 用 Android Studio / SDK 36，iOS 用 Xcode。当前没有可直接分发的通用安装包。 |
| 自己的服务凭据 | 按需准备 NVIDIA NIM 或兼容 ASR 的 API Key、兼容 Chat Completions 的 LLM Key、飞书 CLI 登录或飞书应用／用户令牌。不要复制作者的个人配置。 |

服务是**单人部署**：拿到服务访问口令的人可以管理录音和供应商设置。不适合直接给多个互不信任的用户共用。录音、数据库、凭据及签名都应单独备份；GitHub 只保存源码。

## 第一步：取得源码并在本机启动服务

从公开仓库克隆并运行：

```bash
git clone https://github.com/Eliqi797/open-feishu-recording-bean.git
cd open-feishu-recording-bean
python3 -m venv .venv
cp .env.example .env
.venv/bin/python -m bean.server --data data --port 8765
```

服务默认只监听 `127.0.0.1:8765`。另一个终端运行 `curl http://127.0.0.1:8765/healthz`，收到 `status: ok` 表示本机 HTTP 服务就绪；这**不表示**蓝牙、转写或飞书已验证。首次启动会在 `data/access-token` 创建访问口令。只在自己设备上读取它，不要贴进 issue、日志或聊天，也不要提交到 Git。

基础上传和测试使用 Python 标准库。需要 NVIDIA NIM 时，在虚拟环境中另行安装 `requirements-nim.txt`；需要兼容回听和音频处理时确认 `ffmpeg -version` 正常。供应商参数可在 `.env` 或 App 的「设置」中配置，字段解释见[配置指南](CONFIGURATION.md)。

手机访问需要 HTTPS 反向代理。请按[部署指南](DEPLOYMENT.md)建立独立系统用户、数据目录、域名、证书和备份；不要将 8765 端口直接暴露到公网，也不要把现有其他服务的数据目录拿来共用。完成公网地址前，先让 `AUTO_PIPELINE=0`，逐项验证供应商和飞书身份。

## 第二步：安装手机 App

| 平台 | 从源码安装 | 设备热点说明 |
| --- | --- | --- |
| HarmonyOS | 按[鸿蒙工程说明](../harmony/README.md)准备 DevEco 工程、SDK 和自己的调试签名；主方案是普通 App。 | 系统会请求蓝牙和 Wi-Fi 权限。 |
| Android | 用 Android Studio 打开 `android/`，安装 Android 36 SDK；运行 `./gradlew :app:assembleDebug` 后在自己的手机上安装并授权蓝牙、附近设备及热点连接。 | 系统弹出 Wi-Fi 连接提示时允许；一批录音只需加入一次设备热点。 |
| iOS | 用 Xcode 打开 `ios/RecordingBean.xcodeproj`，选择自己的 Team 后签名安装。最低系统版本为 iOS 17。 | 免费个人 Team 使用手动入网：按 App 提示到 iPhone Wi-Fi 设置加入录音豆临时热点，再返回 App；一批文件只需加入一次。 |

各平台当前的真机实测边界和编译细节见[跨平台客户端](CROSS_PLATFORM.md)。不同设备固件、手机系统和签名条件可能改变连接表现；不要把编译通过当作完整传输验收。

## 第三步：连接自己的服务和供应商

1. 在 App「设置 → 服务连接」填**自己**的 HTTPS 服务地址和 `data/access-token` 中的访问口令，点验证并保存。手机本地口令保存在系统安全存储中。
2. 在「语音转写」选择 NVIDIA Parakeet 中文、NVIDIA Whisper 或兼容 `/audio/transcriptions` 的接口，填写自己服务的 API Key。Whisper 可用于对照，不必每条录音都调用两个模型。
3. 在「智能总结」填写兼容 `/chat/completions` 的 HTTPS 基础地址、模型名和密钥。
4. 在「飞书文档」选择服务器已登录的飞书 CLI、飞书自建应用或手动用户令牌。核对目标身份和文件夹，确认后才开启写入。使用应用身份时，需先给应用相应文档权限；使用个人身份时，Open ID 不匹配会阻止写入。
5. 在「处理与传输」按需开启上传后自动处理。设置只影响**新开始的处理任务**，不会自动重做已完成录音。已有密钥不会回显；密钥输入框留空表示保留原值。

没有 ASR、LLM 或飞书凭据时，也可以先验证设备读取、云端保存和受保护回听。不要为测试而改用别人的飞书账号。

## 第四步：做第一条完整验证

1. 在飞书录音豆上完成一条约 30 秒录音并保留原文件；先确认设备已经停止录音。
2. 打开 App「录音」页，扫描并连接设备。检查顶部连接状态、电量和录音列表；看不到设备时先唤醒录音豆。
3. 使用自动上传或点「高速传输」，按系统提示允许 Wi-Fi 连接。观察下载、上传速度与进度；传输 100% 后仍要等待服务器核验回执。
4. 在「云端录音」看到「已保存」后打开详情，检查原始音频是否可回听，以及 ASR、总结和飞书各阶段的状态。只把内容核对通过的转写和纪要当作可靠记录。
5. 若开启飞书，打开生成的文档，核对录制时间、标题、摘要、原文和待办；在飞书本人账号下确认可见。

服务器保存成功与飞书发布成功是两个阶段。手机断线或退出后，已收到的服务器任务可继续运行；手机上尚未确认的音频缓存应保留，待下次继续传输。录音豆原文件始终保留。

## 常见问题

| 现象 | 先检查 |
| --- | --- |
| 扫描不到或连接中断 | 唤醒录音豆、靠近手机、确认蓝牙权限；不要让另一台手机同时占用设备。设备连接诊断见[跨平台状态](CROSS_PLATFORM.md)。 |
| 高速传输没有开始 | 确认录音已结束，接受手机系统的热点授权；iOS 免费 Team 要手动加入设备热点。不要关闭云端 HTTPS 的证书校验来解决设备热点问题。 |
| 录音显示已上传但没有纪要 | 查看录音详情中 ASR、说话人、总结、飞书各阶段状态；先核对供应商密钥、额度、模型接口、飞书身份与权限。服务状态见 `/api/diagnostics`。 |
| 飞书打不开或写到错误位置 | 检查写入身份、预期 Open ID、文件夹 Token 与文档权限；不要在未核对身份时反复重试创建文档。 |
| 换手机或重装 App | 从自己的 GitHub 克隆源码重新签名安装，并恢复自己的服务地址与口令；录音和任务仍以服务器数据及独立备份为准。 |

接口与处理状态见[API 文档](API.md)，恢复方法见[部署指南](DEPLOYMENT.md)，当前未完成的场景见[状态清单](STATUS_AUDIT.md)。遇到问题时提供平台、系统版本、设备状态和**脱敏后的**错误信息，不要提交音频、令牌、签名或私人飞书文档。
